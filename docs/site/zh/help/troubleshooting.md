# 问题排查 {#troubleshooting}

请根据症状先查看[启动与意外退出](#startup-checks)、[GPU 错误](#gpu-errors)或[恢复步骤](./projects.md#gpu-recovery)。如问题仍未解决，可使用[问题反馈模板](#report-template)。

## 无法启动或意外退出 {#startup-checks}

### 先保留这些信息与数据

- 记录完整错误提示、发生时间以及出错前的操作。截图前请检查是否包含个人信息或不可分享的作品。
- 如果应用仍可操作，请保存场景。如果内容看起来有缺失，请先使用“场景另存为”，避免覆盖完好的保存文件。
- 排查时保留项目与自动保存数据。不要将删除设置或自动保存文件夹作为第一步。

### 按以下顺序检查

1. 请确认[安装步骤](./start.md#app-install)，并从开始菜单启动 HarmoFlow 或 HarmoFlow Trial。如果下载不完整，请从 BOOTH 重新获取同一版本类型的安装程序。保持安装文件完整，不要只移动 `harmoflow.exe`，也不要从不明网站下载所谓的缺失 DLL。
2. 确认使用 Windows，以及支持 Vulkan 1.2 的 GPU 和驱动程序。如需更新驱动，请使用电脑或 GPU 厂商的官方来源。使用应用不需要安装 Vulkan SDK。
3. 保存其他应用中的工作后，关闭游戏、视频编辑器等高 GPU 负载应用，再重新启动 HarmoFlow。必要时重新启动 Windows。
4. 如果应用能够打开，请保护好原项目，使用较低工作分辨率和小型新项目进行测试。分别记录问题是否在启动后立即出现、仅限某个模型，或发生在更改分辨率、绘画、导出时。
5. 如果同一错误反复出现，请避免在有未保存内容时反复复现，并附上[诊断信息](#diagnostic-info)联系支持。不建议通过关闭 Windows 警告或安全软件来继续操作。

::: warning 意外退出后
并非每次崩溃都会出现恢复提示。GPU 错误后的恢复仅在恢复用自动保存成功且数据仍可用时才有可能。若没有提示，请检查上次保存的场景或可用的[自动保存](./projects.md#autosave-location)。无法保证恢复所有未保存的更改。
:::

## 根据 GPU 错误提示进行排查 {#gpu-errors}

| 提示或症状 | 下一步检查 |
| --- | --- |
| GPU 显存 (VRAM) 不足 | 关闭其他使用 GPU 的应用，并尝试降低纹理分辨率。部件（纹理集）越多，所需内存越大。“偏好设置 → VRAM”也可用于降低预览内存占用 |
| GPU 停止响应 | 关闭其他高负载应用，并检查官方驱动更新。记录正在执行的操作及停止响应前的情况 |
| GPU 已重置 | 记录是否发生在从睡眠唤醒或更新驱动后。若反复出现，可考虑更新官方驱动，并报告发生条件 |
| 其他 GPU 错误 | 记录“详细信息”中的完整内容，以及 GPU 型号、驱动版本和当时执行的操作 |

内存不足时，某些操作可以退回之前的状态而不退出应用。如果应用仍然打开，请检查并保存场景，降低负载后再试。若提示需要退出或重新启动，请按照[GPU 错误后的恢复步骤](./projects.md#gpu-recovery)操作。每次只调整一项分辨率或 VRAM 设置，更便于确认影响因素。

## UV 只显示外框

::: details 解决方法
将“线框设置”中的显示方式改为“三角形”。UV 壳显示模式只绘制 UV 岛的外轮廓。


:::

## 线框过深或过于密集

::: details 解决方法
降低线宽和不透明度，或切换到 UV 壳显示模式。如果希望查看纹理本身，可以关闭 UV 线框。


:::

## 无法切换部件

::: details 解决方法
如果导入的模型只有一个部件，切换栏将不可用。模型有多个部件时，可在通道面板顶部选择。


:::

## 网格贴图没有显示

::: details 解决方法
请等待自动烘焙完成。如果出现错误，请查看提示内容，并尝试“重新烘焙”。更换导入的模型后，旧的处理结果会被丢弃。


:::


## 图层面板的显示

通过图层面板的齿轮菜单可以切换内容预览，此设置会保存到 UI 布局中。预览以小型 UV 图片显示已绘制材质的 BaseColor。系统会复用 GPU 烘焙结果，而不会为每一行重新烘焙整个图层。

文件夹行的高度低于绘画图层行，选中行的内侧会显示边框。将内容拖到图层名称的上半部或下半部时，相应的插入位置会显示提示线。拖到文件夹中央时会显示边框，内容会移入文件夹。拖到文件夹的顶部或底部边缘时，会显示插入位置提示线，可将内容排在包含子图层的整个文件夹之前或之后。移动文件夹时会保留其子图层，并支持 Undo/Redo。

## 查看版本与日志 {#diagnostic-info}

- **版本**：记录“帮助 → 关于 HarmoFlow”中的 `v…`。如能看到标题栏中央方括号内的构建时间，也请一并记录。如果无法启动，请提供下载的发行文件名称与版本。
- **GPU 与 Windows**：记录 Windows 版本、GPU 完整型号、VRAM 容量和显卡驱动版本。如果有多个 GPU，请尽可能全部列出。
- **应用日志**：通过“窗口 → 控制台”查看处理结果，使用“复制”获取文本。控制台在内存中保留本次运行的最多 5,000 条记录；它不是重新启动后可读取上次记录的持久日志文件。能获取时，请在退出、重新启动或清空之前保留。

::: tip 复制和分享日志
即使控制台已按条件筛选显示内容，“复制”仍会复制保留的全部日志。请先粘贴到文本编辑器，仅保留问题发生时间前后等相关部分，并隐去用户名、本地完整路径及保密文件名。如果应用无法启动而无法收集日志，请说明这一点，并提供错误提示内容。
:::

## 问题反馈模板 {#report-template}

复制以下模板，填写已知信息，通过[豆々庵的 BOOTH 商店](https://mametarovv.booth.pm/)联系销售方。不清楚的项目可填写“不详”。请勿填写密码或购买时的支付信息。

```text
问题概述：
HarmoFlow 版本／正式版或试用版：
构建时间（如已知）：
Windows 版本：
GPU 型号／VRAM 容量／驱动版本：
发生日期与时间：
当时执行的操作：
复现步骤：1. … 2. … 3. …
预期结果／实际结果：
发生频率（每次／偶尔／仅一次）：
新项目中是否也会发生／是否仅限特定数据：
模型格式、部件数、工作分辨率（如已知）：
额外插件的有无、名称与版本：
完整错误提示：
上次成功保存的时点／恢复提示及恢复结果：
已尝试的处理方法与结果：
附件（相关日志、图片或复现示例）：
是否可以分享示例／分享范围限制：
```

无需一开始就发送整个项目。日志、图片和示例应限于必要的最小范围，并检查是否包含未发布作品、客户信息或第三方素材。购买的素材应先确认再分发条款；如无权分享，请改用能复现同一问题的小型自制示例，或说明无法分享数据。
