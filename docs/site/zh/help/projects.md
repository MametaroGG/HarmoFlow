# 项目、保存与恢复 {#projects}

<GuideFlow kind="save-export" />

## 新建项目与导入模型

通过“文件 → 新建项目”选择保存位置，再使用“导入模型”加载模型。支持 FBX、OBJ、glTF / GLB、DAE、PLY、STL、3DS、BLEND。制作纹理前，请为模型准备好 UV。对于不含 UV 的格式或数据，支持导入并不代表可以进行纹理编辑。

项目是集中管理资源和场景的工作文件夹。在“项目设置”中可以更改根文件夹和纹理分辨率。场景扩展名为 `.harmos`。


导入包内素材请参阅[Unity Package导入](./assets.md#unitypackage-import)。FBX中的变形及部件显示请参阅[网格与形态键](./viewport.md#mesh-visibility)。

在[Ver.0.2.0](https://github.com/MametaroGG/HarmoFlow/releases/tag/Ver.0.2.0)中，新启动的会话复用共用的“默认”项目，不再每次都创建新的临时项目。“打开场景”的文件筛选统一为`.harmos`，请选择需要继续编辑的场景文件。

### 新场景与项目文件夹 {#new-scene-project-root}

“新建项目”会创建包含scenes、assets、autosave和workspace.json的文件夹。请按Ctrl+S保存新场景。同一项目中的多个场景可以共享资源。

“文件 → 新建场景”（Ctrl+N）会使用当前工作分辨率开始一个新场景。如果已有更改，可选择“保存并新建”“不保存并新建”或“取消”。移动相机等操作也可能触发保存提示。

“项目设置 → 更改...”以及主页的项目选择用于指定项目文件夹，不会关闭当前场景，也不会移动已有场景和资源。切换场景请使用“打开场景”。需要打开特定版本时，请直接选择对应的.harmos文件。

## 选择合适的保存方式

| 操作 | 用途 |
| --- | --- |
| 保存场景 | 保存当前编辑状态。Ctrl+S |
| 场景另存为 | 以其他名称保存编辑状态。Ctrl+Shift+S。保存到另一个项目时，也会将当前库中的资产复制到目标项目。 |
| 递增保存 | 递增编号并保留版本。Ctrl+Alt+S |
| 打开场景 | 从已保存的编辑状态继续工作 |
| 导出资源包 | 将项目打包为 `.harmopackage` 以便携带 |
| 再次导出资源包 | 不显示确认对话框，立即覆盖上次导出的资源包。执行前请将光标停留在菜单项上，核对输出路径 |
| 打开资源包 | 解压到设置的位置并打开 |
| 打开资源包到... | 选择本次解压位置并打开 |

::: warning 保存到另一个项目前
保存到另一个项目时，会将当前工作库中的全部资产合并到目标位置，包括当前场景未使用的资产。如果目标位置存在相同相对路径的文件，会不经确认直接覆盖，可能影响目标项目中的其他场景。此复制操作不会删除仅存在于目标位置的文件。

保存到已有项目前，请先备份。要创建独立副本，请保存到新建的空项目文件夹。使用同一资产保存位置的常规“场景另存为”和“递增保存”不会执行此复制。
:::

导出资源包时会先保存当前场景。尚未保存的工作会在资源包旁创建项目文件夹。资源包包含workspace.json以及scenes、assets和autosave文件夹，不包含项目根目录中的其他文件。分享前，请检查其他场景和自动保存中是否有不宜分享的内容。

### 递增保存与打包位置 {#save-package-locations}

“递增保存”会在当前场景所在文件夹中创建name_001.harmos、name_002.harmos等文件，并在新版本中继续工作。各版本共享项目资源，不会在每次保存时复制整个项目。

“打开资源包”默认解压到下载文件夹，可在“偏好设置 → 常规 → 资源包解压文件夹”中更改。“打开资源包到...”只为本次操作选择解压位置。如果已有同名且非空的文件夹，会使用带编号的其他文件夹。

应用会记住“再次导出资源包”的目标位置。执行前请将鼠标悬停在该命令上核对路径，切换项目后也要确认。

## 场景的版本兼容性 {#scene-version-compatibility}

::: warning 使用Ver.0.3.0功能之前
重新打开包含材质蒙版变换的项目需要Ver.0.3.0或更新版本。重现新的笔压流量、绘制质量及纤细起收笔效果，同样需要Ver.0.3.0或更新版本。已保存的旧笔画保持原有粗细。

还需使用旧版时，请在用新功能保存之前，通过“场景另存为”或“递增保存”创建独立文件，并保留原项目，避免覆盖。
:::

::: warning 使用Ver.0.2.0新功能保存前
使用[Ver.0.2.0](https://github.com/MametaroGG/HarmoFlow/releases/tag/Ver.0.2.0)新功能保存的场景，可能无法在旧版中正确打开。如仍需使用旧版，请用“场景另存为”或“递增保存”创建独立文件，并保留修改前的原文件，避免覆盖。
:::

::: warning 还需使用Ver.0.1.1或更早版本时
包含[Ver.0.1.2](https://github.com/MametaroGG/HarmoFlow/releases/tag/Ver.0.1.2)新增3D路径的场景，无法在Ver.0.1.1或更早版本中打开。还需在旧版中使用的场景，请保留修改前的文件。
:::

添加新3D路径，或在3D视图中重新创建以前以UV坐标保存的路径之前，请使用“场景另存为”或“递增保存”创建独立文件，并保留原文件，避免将其覆盖。哪些路径需要重新创建，请参阅[路径的UV岛边界](./paths.md#path-uv-island-boundaries)。

## 自动保存与恢复

定时自动保存默认关闭。初始设置为每5分钟保存一次、仅在有更改时保存、保留20个快照。界面可设置保留0〜50个，0表示全部保留。正在绘制或执行其他处理时，定时保存会等待。“立即自动保存”在定时保存关闭时也可使用。

在“偏好设置 → 自动保存”中启用自动保存，并设置间隔（1〜60 分钟）、前缀、是否仅在有更改时保存，以及保留数量。保留数量为 0 时会保留全部文件。也可使用“立即自动保存”或打开保存文件夹。

通过“文件 → 恢复自动保存”选择已保存的快照。“恢复上次保存”会根据可用的上次保存创建并打开一个独立的恢复场景，保留原场景文件。确认恢复后的内容无误后，请正常保存场景。

### 查找和选择自动保存 {#autosave-location}

已保存项目的快照位于项目文件夹内的 `autosave` 中。未保存会话使用 HarmoFlow 的应用数据区域。请通过“偏好设置 → 自动保存”中的“当前文件夹”和“打开自动保存文件夹”确认实际位置。

在“恢复自动保存”中，先核对日期、时间和目标，再选择快照。属于项目的自动保存会以 `原场景名_recovered_编号` 的名称，作为独立场景加入项目的场景文件夹。项目中缺失的资源会被恢复，已有资源文件不会改变。未保存会话的自动保存会作为未保存场景打开，正常保存时可选择保存位置。恢复前应用也会尝试自动保存当前工作，但重要内容请先正常保存。

自动保存不能替代正常保存或备份。保留数量限制可能清理较旧的快照，因此需要长期保留的版本应另存、递增保存或备份。排查恢复问题时，请勿删除或移动原项目及自动保存数据。

## 在 GPU 错误后恢复工作 {#gpu-recovery}

::: warning 恢复需要成功的自动保存
GPU 错误后，应用会尝试创建恢复用自动保存，但不一定成功。保存失败、数据缺失或强制退出等情况可能导致无法恢复，也无法保证找回所有未保存的更改。
:::

1. 记录错误提示中的原因、操作和详细信息，确认提示是“工作已自动保存”还是“恢复用自动保存失败”。保存成功时，可选择“重新启动”，或选择“退出”后再次启动 HarmoFlow。
2. 下次启动时如出现“恢复工作”，请确认目标后选择“恢复”，并等待加载结束。如果原项目不可用，或工作原本尚未保存，内容可能作为未保存场景打开。
3. 检查恢复后的模型、图层、最近绘制的内容、材质和图片。能正常打开并不代表所有内容都已完整恢复。
4. 确认内容后，使用“保存场景”（Ctrl+S）。**仅执行恢复不会覆盖原场景文件；在正常保存之前，磁盘上的原文件保持不变。** 如果还想保留原有保存，请使用“场景另存为”。

如果打算稍后恢复，**请先将鼠标悬停在“暂不恢复”按钮上，在点击前记下工具提示中的自动保存路径。** 点击后会关闭恢复提示，但不会删除自动保存数据。

稍后恢复已保存的工作时，请先打开原项目，再选择“文件 → 恢复自动保存”。列表只显示当前项目的自动保存；未保存会话则显示应用数据目录中的自动保存。如果列表中没有目标快照，请将记录的路径与“当前文件夹”进行核对。

若没有提示、保存失败或恢复时再次退出，请保留原始数据，查看[GPU 错误排查与反馈](./troubleshooting.md#gpu-errors)。反复尝试恢复前，请先检查 GPU 负载与驱动状态。
